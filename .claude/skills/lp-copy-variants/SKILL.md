## このスキルの流れ

1. **STEP 1**: ヒアリング（対象セクション・ペルソナ・訴求の方向性）
2. **STEP 2**: knowledgeファイル読み込み
3. **STEP 3**: 訴求軸×ペルソナでコピーセットを生成
4. **STEP 4**: 一覧出力 → ユーザーが選択
5. **STEP 5**: 選択案をLPファイルに反映（任意）

---

## STEP 1: ヒアリング

以下が未指定の場合は確認する。

| 項目 | 内容 |
|---|---|
| 対象LP | ファイルパス or 用途（例: Meta広告流入用FV） |
| 対象セクション | FV / ラストCTA / STATSバッジ / その他 |
| ターゲットペルソナ | タイパ重視 / ミスマッチ回避（単願）/ ミスマッチ回避（併願）/ 全員 |
| 文字数制限 | キャッチコピーの最大文字数（例: 20字以内） |

---

## STEP 2: knowledgeファイル読み込み

以下を**すべて**読んでからコピー生成を始める。

| ファイル | 読み取る情報 |
|---|---|
| `knowledge/business/business-overview.md` | USP・数値実績・KPI・サービス内容 |
| `knowledge/target/who_what_how.md` | ペルソナ3セグメント・インサイト・ペインポイント・提供価値 |
| `knowledge/target/customer_info.md` | 顧客のリアルな声・言葉（あれば） |

## STEP 3: コピーセット生成

### 訴求軸の定義

| 訴求軸 | 切り口 | 刺さるペルソナ |
|---|---|---|
| **課題解決型** | 「〇〇で悩んでいる？」から入る。ペインを言語化して共感を取る | ミスマッチ回避（単願・併願） |
| **ベネフィット型** | 得られる未来・価値を前面に出す。就活・収入・快適さなど | タイパ重視・全般 |
| **数字型** | 実績・信頼指標で刺す。1.5万件・2.7万人・30秒 など | 慎重派・比較検討派 |
| **共感型** | 「わかる、その気持ち」系。感情に寄り添うトーン | ミスマッチ回避（単願） |
| **差別化型** | 「他のバイトと違う理由」を前面に出す | 併願型（比較中） |

### 1セットの構成

各訴求軸につき以下の3点をセットで出力する。

```
【キャッチコピー】  ← 大見出し（目安: 15〜25字）
【サブコピー】     ← 補足説明（1〜2行、35〜50字程度）
【CTA文言】        ← ボタン文言（8〜15字程度）
```

---

## STEP 4: ユーザー確認

出力後に以下を確認する。

- 「どの案が近いですか？」
- 「トーン調整（もっと強く / もっと柔らかく）はありますか？」
- 「文字数を変えたいセクションはありますか？」

---

## STEP 5: LPファイルへの反映（任意）

ユーザーが案を選んだ場合、対象LPファイルの該当テキストを Edit で書き換える。

```
対象ファイル: lp/〇〇.html
変更箇所:
  - .fv__copy のテキスト → 選択キャッチコピー
  - .fv__sub のテキスト  → 選択サブコピー
  - .line_btn のテキスト → 選択CTA文言
```

書き換え後は `scripts/analysis/screenshot_lp.py` でプレビューを取得して確認する。

---

## コピー生成の原則

| ルール | 内容 |
|---|---|
| 自分事化 | 「大学生」より「あなた」「塾バイト探してる人」に語りかける |
| 数字は具体的に | 「たくさん」より「1.5万件」「2.7万人」を使う |
| CTA は動詞で始める | 「診断する」「登録する」「チェックする」（体言止めにしない） |
| ペインは言い過ぎない | 「失敗したら怖い」より「ミスマッチしたくない」程度のトーンに留める |
| 就活軸は慎重に | 就活ガクチカ訴求は刺さるが離脱にも繋がる。サブコピーで添える程度に |
